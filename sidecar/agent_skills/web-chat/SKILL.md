# 聊天模式（Web Chat）

> 这是一套**独立**的执行形态（§0.4 第四形态），不是 Agent 任务、不是智能填表、不是回放。
> 引擎是耐久相位状态机（`core/web_chat/engine.ts`）；本 Skill 是它的**领域纪律手册**。
> 引擎不认识浏览器/模型/磁盘，本 Skill 不认识代码——两者都**不得**把规则写进对方。

## 这条链路在做什么

```
宿主给名单 → 逐人开会话 → 读会话 → 判断要不要说 → 生成一条 → 去重/闸门 → 发送 → 回读确认 → 记进上下文
                                              ↑                                        ↓
                                      短复查 + 自动聊天决定                 每联系人独立记忆（摘要/事实/角度）
```

**每一轮只发一条消息**。发不发、发几条、什么时候发，全由确定性代码决定，
**不交给模型**（§11：禁止「催模型收尾」那类问题的变体）。

## 五条不可违反的纪律

### 1. 静音（绝不截图）

聊天模式**不产生**以下任何副作用，且由**源码级回归测试**强制
（`sidecar/tests/chat-engine.mjs`：扫描 `core/web_chat/**` 与 `bu_agent/chat_*.ts`，出现即红）：

`screenshot` · `panorama_capture` · `som_mark` · `a11y_full_tree` · `safe_page_digest` · `arbiter_shadow`

等待新消息**只能**靠页内 `MutationObserver`（事件驱动）。轮询是**兜底**且必须如实记
`chat_wait_fallback_poll`——不许假装事件驱动。**禁止**用「每秒截图看有没有新消息」这种实现。

### 2. 人优先（R7）

用户正在这个环境里打字/点击 → 立刻让位（`chat_patrol_yield`，理由 `user_active`）。
聊天**永远不跟用户抢输入**，也不劫持用户当前在看的标签（用自己开的专用聊天标签）。

### 3. 记性在文件里，不在模型里

每个联系人一份独立上下文（`chat_context/{site}/{contact}/`）：

| 文件 | 内容 | 纪律 |
|------|------|------|
| `thread.jsonl` | 会话流水 | **落盘前脱敏**，一次性码绝不入库（R2） |
| `summary.json` | 滚动摘要 + 已覆盖位置 | **只能从「旧摘要 + 未覆盖的原始消息」生成** |
| `facts.json` | 关于对方的长期事实 | 只追加去重、按条数限量、**不参与摘要压缩** |
| `angles.json` | 已用过的切入角度 | 重复角度**不入库**（宁丢角度不丢消息） |
| `visit.json` | 回访状态 + 下次到期 | 必须持久化，否则重启即回访风暴 |

**防递归退化**（摘要反复总结会磨成废话）三条硬规则：

1. 没有被覆盖的**原始消息**就**不压缩**（禁止「拿摘要总结摘要」）；
2. 稳定事实独立存放，摘要被裁剪时事实**一条都不丢**；
3. 压缩代数到顶后**不再压缩**，只推进覆盖位置。

`coveredUpToId` **只能前进**：模型偶尔回吐旧位置也不会让已覆盖内容重新变成未覆盖。

### 4. 回访有节制、必须有由头

首次回访至少隔 ~48h，之后拉长到 4–7 天；一轮 3–5 次；一轮后冷却 7–10 天；
长期静默 90–180 天才允许重启新一轮。**间隔由线程 key 派生确定性抖动**（不是随机数）。

**任何回复、异议、退订、明确拒绝 → 立即停止全部后续**（`opted_out`）。
**禁止空访**：没有新角度就不发，如实记 `chat_followup_skipped` + 原因（`no_new_angle`）。
禁止「在吗 / 还在考虑吗」这种没有由头的招呼。

### 5. 绝不代发敏感内容

- **一次性码**（短信码/TOTP/token）：不代发、不落盘、不编造（R2）。命中即**不发**。
- **支付/证件语义**（转账/付款/卡号/CVV/身份证/护照）：命中即停并**转人工**（R1）。
- 对方索要以上内容 → 委婉拒绝并转移话题，**不汇报**、不帮忙取。

口径在 `core/web_chat/chat_redaction.ts` 一处定义，**发送闸门与落盘脱敏共用**——
两处各写一份正则会分叉成「发不出去却已写进磁盘」，那是极难查的缝。

## 话术纪律（写草稿时）

- 只输出**这一条**消息，不解释、不加引号、不写多条；用对方使用的语言。
- 长度像真人打字：中文 8~40 字，最多两句话。
- **必须呼应上文的具体内容**（对方刚说的某件事/某个词），不许说泛泛之词。
- **严禁复述/改写/换同义词重复**自己说过的话，也不要重复同一个开场套路。
- 不出现机器痕迹：不写「作为AI」「我代表」，不堆感叹号，不用客服话术
  （「已收到」「感谢咨询」），不群发口吻。
- **不编造敏感与身份**（验证码/银行卡/证件/假人设）；商业目标下对方问价时要给渠道大致价，禁止空推「还没官宣」。对方纠正事实时先认错接住。
- **主动回访时绝不提**「上次」「之前联系过」「好久没聊」——那会暴露这是自动跟进。

## 输出契约

草稿（`chat_prompt.ts`）：

```json
{"text":"要发送的消息","angle":"这一条用的切入角度（4~10字）"}
```

摘要+事实（`chat_memory.ts`）：

```json
{"summary":"关系进展的紧凑摘要","facts":["关于对方的稳定事实","..."]}
```

两者都**严格解析、绝不放行空内容**；解析失败按「本轮不更新/不发」处理，不猜。

## 与其它模块的边界

| 事项 | 归谁 | 不归谁 |
|------|------|--------|
| 要不要发、发几次、何时发 | `engine.ts` + `cadence.ts` | 模型 |
| 读页面（会话/发送） | `bu_agent/chat_actions.ts` | 引擎 |
| 记忆读写 | `context_store.ts` | 引擎直写磁盘 |
| 提示词与解析 | `chat_prompt.ts` / `chat_memory.ts` | 宿主 |
| 名单与调度 | Host（DB `chat_threads` + 看门狗） | 引擎自己维护名单 |
| 席位与互斥 | `engine_mutex` + Host 会话管理 | 聊天自己开通道 |

**禁止**：在 `chat_engine` 里另起半套 Agent 循环；把聊天日志混进通用监视日志；
用附件图取 OTP；为过检测改指纹；把站点选择器写进核心。

## 加一个站点 = 加一份描述符（不改代码）

站点差异**不是**代码分支，而是**一份声明式描述符**（`sidecar/connectors/*.json`）。
三种来源，按优先级取用：**学来的 > 内置 > 通用读法**。

| 路径 | 谁写 | 说明 |
|------|------|------|
| `sidecar/connectors/*.json` | 随包发布（内置） | 覆盖主流站点；升级会替换 |
| `<环境 userDataDir>/connectors/_learned/*.json` | 「设置 → 聊天 → 站点支持 → 学习本站」 | 随环境删除一并清掉，**不会**带给新建的环境 |

学习流程（设置 →「聊天」Tab → 站点支持 →「学习本站」，Host 命令 `chat_learn_site`；总览/删除走无浏览器的一次性 CLI）：

```
采集页面结构事实（0 token，绝不把 HTML 喂给模型）
  → 模型只输出声明式 JSON 描述符
  → 机器自检：拿「模型没见过的」held-out 消息逐条核对（方向/内容/附件/骨架）
  → 通过才落盘；不通过就把逐条差异摆出来再改一轮
```

三条纪律：

1. **只喂结构化事实，绝不喂 HTML**：喂 HTML 会把模型的猜谜当结论，产出看起来能用、
   实际读错的描述符。
2. **描述符里没有代码**：只有选择器与映射（JSON Pointer），没有函数、没有 `eval`。
3. **写入要单独验**：读通过 ≠ 写可用。给自己发一条自检消息再读回来逐字核对
   （自测对象必须是你自己的会话/收藏夹 —— 引擎绝不猜谁是你）。

站点**读得到但总读错**（方向反了、读到相邻文本、附件当文字）时，先来看这里：
多半是该站点还没有描述符，或者描述符被熔断了（连续失败 3 次即停用，需显式重新启用）。

## 发图与图库

聊天可以发**图库**里的实拍图，不能发语音或视频。

- 默认图在 `sidecar/chat_media/`；用户可在「设置 → 聊天 → 发图图库」改成自己的文件夹。
- 文件夹名 = 品类（中文或英文），文件名 = 颜色/角度。
- 对方要图时，引擎按文件名/文件夹名匹配后走页面附件按钮发出去（不调站点内部接口）。
- 匹配不到就老实说备图，不会乱发一张。
- 自定义目录不存在或为空时**不回落**内置图库（避免「以为在用自己的文件夹」）。
- 对方要语音/视频：用一句自然借口带过，有对应图就先发图；**不要主动说**「我不能发语音/视频」。

便携包必须带上默认的 `chat_media/`；用户自定义路径指向本机目录，不随包拷。

## 什么时候停

- **应用关掉即值守停止**：聊天不会在应用之外存续 —— 总开关关闭时不注册任何定时器，
  进程退出即不再有任何自动拉起；每联系人上下文留在磁盘上等你下次打开。
- **用户接管即让位**：检测到用户在该环境有输入，本轮立刻让位（`chat_patrol_yield`）。
- **对方拒绝即停**：任何回复/异议/退订 → 该联系人后续追发全部停止。
