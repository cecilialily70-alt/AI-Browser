# 长按按钮（按住不放）验证码

## 何时用

页面出现「长按 / 長按 / 按住不放 / Press and hold」一类人机验证提示，或验证码控件位于
`#arkose` / `#fc-iframe` / `arkoselabs.com` / `funcaptcha.com` 一类容器内时：

本轮唯一动作：`{"solve_captcha": {}}`

（可用 `{"solve_captcha": {"strategy": "press_hold_captcha"}}` 强制指定；这不是新工具，失败勿换别名顶次数。）

> 这类题面**点一下就必然失败**：必须整体按住，直到进度条填满（各站快慢不一，3s~8s 都常见）。
> 按住时长**不固定**：由页面反馈决定何时松手，不要自己缩短。

## 工具行为

1. 类型门禁 `press_hold_captcha`：主文档 + 所有 iframe 的题面一起看；Arkose 容器可直接成立，
   弱提示词（如只写「按住」）必须与验证码语义共存，滑块题的「按住滑块」不会被抢路由。
2. **组件没就绪会自己等**：题面/骨架先出现、按钮几秒后才注入是常态。若页面上看不到长按按钮，
   本工具会按预算轮询等待（默认最多 30s，组件一出现立即继续）再定位 —— 这是工具内部行为，
   **不要因为「第一次没找到」就立刻重发 solve_captcha 顶次数**，也不要自己去 wait 后重试。
3. **定位按形状，不按文案**：每个站的按钮文字都不同（「按住」/「長按按鈕」/「Press and hold」/「Hold」…），
   因此取「挑战区内的宽扁主控件（药丸形）」为长按目标，文案命中只作加分；坐标一律 DOM 实测
   （框架局部矩形 + 框架在主文档视口偏移），不做视觉猜点。
4. 鼠标移到按钮中心 → 按下左键**保持到该松手的时刻**（时长自适应，不固定）：
   - 出现成功/失败/框架拆除信号 → 立即松手；
   - 进度条（`role=progressbar` / `aria-valuenow` / 宽度或 `scaleX` 走满）填满 → 再保持约 0.7s 后松手（松手时刻常是站点结算时刻，卡在 95% 就松会像中途放弃）；
   - 页面仍提示「长按」或控件带进度条可观测 → 继续按住（下限约 3s，上限 15s 保险丝）；
   - 既无「仍要按住」反馈、也无进度条可观测（疑似误判控件）→ 按住下限后收手。
5. 等 1~2s 验收：隐藏 token 输入有值、挑战框架被拆除且无残留可见验证容器、或页内成功文案 = 通过。
6. 未通过则**无障碍备用方案**：点无障碍入口（按「无障碍/accessib/訪問性/語音/聽覺」语义 + 小图标识别）
   → 只在**该入口所在框架**内等长按按钮/宽扁主操作出现后再试一次 → 再验收。
   若一开始只有无障碍入口、没有长按按钮，直接走这条路径。
7. 等待后仍找不到宽扁主控件时**诚实返回 unsupported**（交由重试/HITL），绝不乱按或猜坐标。

## 禁止

- 手点一下（或普通 `click`）就当作「按过了」
- 把文案写死成某个站的说法；找不到就不找了
- 拖动/刷新换题；同轮夹带 navigate
- 在挑战容器外乱点宽扁按钮（会误推进注册/下单流程）
- 改指纹或注入绕过脚本
